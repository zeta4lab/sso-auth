# 논의 아젠다

구현 전에 확정할 항목이다. 정해진 항목은 **결정**으로 옮기고 날짜를 적는다.

## 결정

### 2026-09-28 · 대상은 서버 간 호출(M2M)만
이 인증이 다루는 대상은 **서비스 간 호출**이다. 웹 SPA 로그인, 모바일 앱 로그인,
zeta4c 연동은 현재 범위가 아니다. 사람이 브라우저에서 로그인하는 흐름이 없으므로
인증 코드 플로우·동의 화면·로그인 UI·브라우저 세션 쿠키·단일 로그아웃(SLO)·SAML 2.0은
범위에서 제외한다. 범위가 바뀌면 이 결정을 먼저 갱신한다.

### 2026-09-28 · 신규 구축, 운영 서비스, 외부 파트너 포함, 컨테이너 환경
- 기존 서비스 간 인증 수단이 **없다.** 마이그레이션 제약이 없으므로 처음부터 올바른 방식을 고른다.
- 결과물은 **실제 운영에 쓴다.** 가용성·시크릿 회전·폐기·감사 로그를 처음부터 설계에 넣는다.
- 호출자에 **외부 파트너가 포함된다.** 내가 통제하지 않는 주체가 붙으므로
  클라이언트 등록, 시크릿 발급·회전, 테넌트/파트너 분리, 파트너별 권한 범위가 필요하다.
- 실행 환경은 **도커/쿠버네티스**다.

### 2026-09-28 · 신원 확인은 OAuth 2.0 client_credentials
외부 파트너가 포함되는 M2M이므로 다음과 같이 정한다.

- **client_credentials로 단기 액세스 토큰 발급.** 폐기가 TTL로 자연히 이루어지고,
  파트너별 권한을 스코프로 분리할 수 있으며, 파트너 쪽 구현 부담이 가장 낮은 표준이다.
- **비대칭 서명(RS256/ES256) + JWKS 공개.** 리소스 서버가 토큰 서버에 묻지 않고
  로컬 검증하므로, 토큰 서버가 잠시 죽어도 이미 발급된 호출은 계속 통과한다.
- **audience 제한**으로 토큰이 의도한 API에서만 쓰이게 한다.

탈락 사유를 함께 남긴다.

- **공유 API 키** — 회전·폐기·감사가 안 되고 유출 시 범위를 좁힐 수 없다.
- **mTLS / SPIFFE** — 내부 워크로드에는 좋으나 외부 파트너에게 인증서 발급·회전
  인프라를 강제해야 해서 온보딩 비용이 크다. 내부 전용 구간에 한해 나중에 병행 검토.
- **SAML** — 사람 로그인·레거시 기업 연동용이며 M2M에 불필요하다.

`private_key_jwt`(파트너가 개인키로 서명한 assertion으로 클라이언트 인증)는
공유 시크릿을 없애는 상위 옵션이며, 고신뢰 파트너용으로 나중에 추가할 수 있다.

### 2026-09-28 · Ory Hydra + 자체 관리 계층, TypeScript
토큰 서버는 직접 만들지 않고 **Ory Hydra**를 쓴다. 이 저장소는 파트너 관리·인가 정책·
검증 라이브러리를 맡는다. 근거와 Keycloak·직접 구현 탈락 사유는 [구조](architecture.md)에 있다.

관리 계층 언어는 **TypeScript(Node 22, Fastify)** 다. 작업 호스트에 Go·Docker가 없고
Node만 있어 여기서 빌드·테스트까지 확인할 수 있는 선택지였다. Hydra는 별도 컨테이너이므로
언어가 달라도 무방하다. Go가 필요해지면 관리 계층만 교체하면 된다.

## 열린 항목

### 1. 인가(무엇을 할 수 있는가)
스코프 목록을 누가 정의하고 바꾸는가. 현재는 `<리소스>:<행위>` 형식만 강제하고
실제 스코프 카탈로그는 비어 있다. 리소스 서버별로 어떤 스코프를 요구할지 정해야 한다.

### 2. 클라이언트 등록·시크릿 수명주기
지금은 운영자가 관리 API로 직접 등록한다. 파트너 셀프서비스 온보딩이 필요한지,
회전 겹침 구간을 며칠로 둘지, 파트너에게 시크릿을 어떤 경로로 전달할지 정해야 한다.

### 3. 즉시 폐기 경로
JWKS 로컬 검증은 폐기가 TTL만큼 늦게 반영된다. 사고 시 즉시 차단이 필요하면
리소스 서버가 폐기 목록을 확인하는 경로(캐시된 차단 목록 등)를 추가해야 한다. 필요 여부 결정.

### 4. 운영 수치
액세스 토큰 TTL(현재 기본 15분), 키 회전 주기, 감사 로그 보관 기간, 가용성 목표,
파트너별 토큰 발급 레이트 리밋.

### 5. 관리 API 인증 강화
현재는 환경변수 정적 토큰 하나다. 운영자가 여러 명이거나 감사 추적이 중요해지면
mTLS·OIDC 로그인 등으로 올려야 한다. (`X-Actor` 헤더는 현재 자기신고 값이라 신뢰할 수 없다.)

### 6. Hydra 운영
Hydra 자체의 배포·키 관리·백업·업그레이드 절차. `SECRETS_SYSTEM` 관리 방법.
